## یک فرض رایج که اشتباه از آب درآمد

فرض بدیهی این است: «هرچه خروجی ابزار کوتاه‌تر، هزینه کمتر». تیم GitHub
Copilot CLI این فرض را با یک ابزار کوتاه‌کننده خروجی Shell به‌نام RTK
آزمایش کرد — و نتیجه برعکس شد: وقتی خروجی بیش از حد فشرده می‌شد، Agent
گاهی مجبور می‌شد دستور را دوباره اجرا کند یا جزئیات گم‌شده را جداگانه
بازخوانی کند. نتیجه خالص: توکن کل مصرف‌شده و زمان کل انجام کار **افزایش**
یافت، نه کاهش.

<Callout type="analysis">
  این یافته نکته مهمی درباره معیار اندازه‌گیری دارد: «توکن هر پاسخ» معیار
  درستی برای کارایی نیست؛ معیار درست، «توکن کل + زمان کل برای تکمیل
  وظیفه» است. یک بهینه‌سازی که عدد اول را بهتر می‌کند اما عدد دوم را بدتر،
  در واقع بهینه‌سازی نیست.
</Callout>

## چهار تغییری که واقعاً جواب داد

تیم GitHub چهار تغییر دیگر را، این‌بار درست، به‌صورت جداگانه اول آفلاین و
سپس با آزمایش A/B آنلاین روی کاربران واقعی اعتبارسنجی کرد:

به‌طور مشخص:

1. **فشرده‌سازی انتخابی خروجی** — خروجی شبیه کد (مثل `cat` یا `git diff`)
   دست‌نخورده باقی می‌ماند؛ نتایج جست‌وجو بدون حذف هیچ موردی فقط بازآرایی
   می‌شوند؛ تنها خروجی تکراری مراحل Install/Build/Test/Lint فشرده می‌شود،
   و فقط وقتی صرفه‌جویی واقعاً قابل‌توجه باشد.
2. **حذف پیشوند شماره‌خط از ابزار `view`** — ابزارهای ویرایش فعلی دیگر به
   این پیشوندها نیاز ندارند؛ حذف آن‌ها صرفاً توکن کم می‌کند بدون آسیب به
   عملکرد.
3. **فشرده‌سازی Prompt ابزار Task** — یک حلقه Meta-Prompting، اندازه
   Prompt این ابزار را تقریباً نصف کرد و حدود ۱۳۰۰ توکن در هر نوبت
   صرفه‌جویی می‌کند.
4. **دسته‌بندی اعلان‌های کارهای پس‌زمینه** — وقتی چند Shell یا Sub-agent
   هم‌زمان کار می‌کنند، نتایج به‌جای چند پیام جداگانه، یک‌جا تحویل داده
   می‌شوند.

## درس مهم‌تر از خود اعداد: رگرسیون پنهان

<Callout type="caution">
  یکی از این تغییرات (فشرده‌سازی Prompt ابزار Task) در اولین آزمون آنلاین
  یک رگرسیون پنهان ایجاد کرد: اجرای موازی Agentهای مستقل از بین رفت و
  Agentها به‌جای هم‌زمان، پشت‌سرهم اجرا می‌شدند. این مشکل با یک تست
  رگرسیون کشف شد و رفعش فقط به اضافه‌کردن یک جمله مشخص به Prompt نیاز
  داشت.
</Callout>

<Callout type="tip">
  درس عملی برای هر تیمی که روی بهینه‌سازی هزینه Agent کار می‌کند: هر
  بهینه‌سازی توکن باید مثل هر تغییر کد دیگر، با تست رگرسیون و آزمایش A/B
  آنلاین روی رفتار واقعی بررسی شود — نه فقط با اندازه‌گیری کاهش توکن.
  کاهش توکن که با افت کیفیت یا از دست رفتن یک قابلیت (مثل اجرای موازی)
  همراه باشد، در نهایت هزینه بیشتری تحمیل می‌کند، نه کمتر.
</Callout>
