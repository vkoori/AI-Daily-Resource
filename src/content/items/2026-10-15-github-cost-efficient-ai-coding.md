summary: >
  نکته محوری این مطلب GitHub: تعداد توکن هر پاسخ به‌تنهایی معیار خوبی برای
  کارایی نیست؛ اگر خروجی ابزار بیش از حد کوتاه شود، ممکن است Agent مجبور شود
  دوباره دستور را اجرا یا جزئیات گم‌شده را بازخوانی کند و هزینه کل و زمان کار
  افزایش یابد — دقیقاً همین اتفاق برای یک ابزار کوتاه‌کننده خروجی Shell به‌نام
  RTK در آزمایش‌های GitHub افتاد. تیم GitHub Copilot CLI چهار تغییر را جداگانه
  به‌صورت آفلاین و سپس با A/B آنلاین اعتبارسنجی کرد: (۱) فشرده‌سازی انتخابی
  خروجی — خروجی شبیه کد (مثل `cat`، `git diff`) دست‌نخورده می‌ماند، نتایج
  جست‌وجو بدون حذف مورد بازآرایی می‌شوند، و فقط خروجی تکراری Install/Build/
  Test/Lint فشرده می‌شود (کاهش ۵٫۵٪ در مصرف Credit)؛ (۲) حذف پیشوند شماره‌خط
  از ابزار `view` چون ابزارهای ویرایش فعلی دیگر به آن نیاز ندارند (کاهش ۳٫۱٪)؛
  (۳) فشرده‌سازی Prompt ابزار Task با یک حلقه Meta-Prompting که اندازه Prompt
  را تقریباً نصف کرد و حدود ۱۳۰۰ توکن در هر نوبت صرفه‌جویی می‌کند (کاهش ۲٫۹٪
  هزینه نرمال‌شده)؛ (۴) دسته‌بندی اعلان‌های کارهای پس‌زمینه — نتایج چند Shell/
  Sub-agent هم‌زمان به‌جای چند پیام جدا، یک‌جا تحویل داده می‌شوند (کاهش ۲٫۳٪).
  درس عملی مهم: یکی از تغییرات در اولین آزمون آنلاین یک رگرسیون پنهان ایجاد
  کرد (اجرای موازی Agentهای مستقل از بین رفت) که با یک تست رگرسیون کشف و با
  یک جمله در Prompt رفع شد — نشان می‌دهد بهینه‌سازی هزینه هم باید مثل هر
  تغییر دیگر تست و پایش شود، نه فقط اندازه‌گیری توکن.
