## این موضوع چیست و چرا همچنان مطرح است؟

با افزایش استفاده از Claude Code و ابزارهای مشابه برای وظایف طولانی و
پیچیده، یکی از بزرگ‌ترین چالش‌های عملی، مدیریت محدودیت Context Window
است: وقتی یک جلسهٔ کاری طولانی می‌شود، مکالمه پر از جزئیات نامربوط
می‌شود و کیفیت پاسخ‌ها افت می‌کند. Subagent راه‌حل رسمی Anthropic برای
این مشکل است و این راهنما، با وجود انتشار در ۷ آوریل ۲۰۲۶، همچنان یکی از
منابع پایه برای یادگیری این الگوست — موضوعی که ارزش آموزشی آن با گذر زمان
کم نشده، چون اصول پشت آن (ایزوله‌سازی Context، تفویض کار) هنوز هسته‌ی
طراحی Agentهای کدنویسی است.

## چه مشکلی را حل می‌کند؟

<Callout type="fact" title="تعریف Subagent">
  طبق این راهنما، یک Subagent نمونه‌ای ایزوله از Claude با Context Window
  مستقل خودش است: کاری را می‌گیرد، آن را انجام می‌دهد، و فقط *نتیجه* را به
  مکالمهٔ اصلی برمی‌گرداند — نه کل روند فکری یا جزئیات میانی. راهنما آن را
  به Tabهای مرورگر در یک جلسهٔ Claude Code تشبیه می‌کند.
</Callout>

## چهار الگوی کاربردی که راهنما پیشنهاد می‌دهد

طبق این راهنما، چهار الگوی رایج برای استفادهٔ عملی از Subagent عبارت‌اند
از: تحقیق پیش از پیاده‌سازی (یک Subagent کدبیس را می‌فهمد، سپس Agent اصلی
پیاده‌سازی می‌کند)، تغییرات موازی روی بخش‌های مستقل، بازبینی مستقل (یک
Subagent جدا کدِ تولیدشده را بررسی می‌کند تا Overfitting یا موارد خاص از
قلم‌افتاده را بگیرد)، و جریان‌کار خطی (طراحی → پیاده‌سازی → تست، با تحویل
مشخص بین مراحل).

## چه چیزی توصیهٔ عملی است و چه چیزی باید با زمینهٔ خودتان سنجیده شود؟

<Callout type="analysis" title="اعداد نمونه، نه نتیجهٔ بنچمارک">
  راهنما هیچ عدد عملکردی یا هزینه‌ای مستند ارائه نمی‌دهد؛ جملاتی مثل «سه
  Subagent موازی معمولاً سریع‌تر تمام می‌شوند» یا آستانهٔ «۱۰ فایل یا ۳
  کار مستقل»، نمونه‌هایی برای شهود هستند، نه نتیجهٔ یک سنجش کمّی مستند.
  پیش از اتکا به این آستانه‌ها در تیم خودتان، منطقی است آن‌ها را روی بار
  کاری واقعی خودتان بسنجید — چون سربار واقعی تفویض کار به ابزار، نوع کار و
  مدل مورداستفاده بستگی دارد.
</Callout>

## چه زمانی/برای چه کسی کاربرد دارد؟

این راهنما مستقیماً برای توسعه‌دهندگانی مفید است که Claude Code را برای
وظایف بزرگ‌تر از یک تغییر ساده به کار می‌برند — به‌خصوص کسانی که با افت
کیفیت پاسخ در مکالمه‌های طولانی مواجه شده‌اند. توصیهٔ عملی خودِ راهنما این
است: ابتدا محاوره‌ای شروع کنید (از Claude بخواهید یک Subagent برای کاری
خاص بسازد)، و فقط وقتی یک الگو را به‌طور تکراری نیاز دارید، آن را به
Subagent سفارشی، Skill یا Hook تبدیل کنید — نه برعکس.
