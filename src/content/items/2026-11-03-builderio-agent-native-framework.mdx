## این موضوع چیست و چرا الان مطرح شده؟

یکی از مشکلات تکرارشونده در ساخت اپلیکیشن‌هایی که هم کاربر انسانی و هم
یک Agent هوش مصنوعی آن‌ها را استفاده می‌کنند، این است که معمولاً دو
مسیر جداگانه ساخته می‌شود: یک رابط کاربری برای انسان، و یک مجموعه Tool
یا API مجزا برای Agent — که به‌مرور از هم فاصله می‌گیرند و به دو «نسخهٔ
واقعیت» متفاوت تبدیل می‌شوند. Builder.io (همان شرکت سازندهٔ ابزارهای
توسعهٔ بصری) در ۲ نوامبر ۲۰۲۶ نسخهٔ Beta فریم‌ورک متن‌باز Agent-Native
را روی Product Hunt عرضه کرد: فریم‌ورکی که در آن رابط کاربری و Agent،
به‌جای دو سیستم جدا، دو «مصرف‌کننده‌ی همتا» از یک مجموعه Action و وضعیت
مشترک هستند.

## چه زمانی و برای چه کسی کاربرد دارد؟

Agent-Native برای تیم‌هایی مناسب است که از ابتدا می‌خواهند یک اپلیکیشن
را به‌گونه‌ای طراحی کنند که از روز اول هم با کاربر انسانی و هم با یک
Agent قابل‌استفاده باشد — به‌جای افزودن یک لایهٔ Agent به یک اپلیکیشن
موجود در آخر کار. مناسب‌ترین سناریو، ابزارهای داخلی یا محصولاتی است که
نیاز دارند تیم‌ها بتوانند دستورها، Skillها و حافظهٔ مشترک را بین
کاربران مختلف به اشتراک بگذارند تا Agent، گردش‌کار واقعی تیم را یاد
بگیرد. چون پشتیبانی از Auth، مجوزها و همکاری بلادرنگ به‌صورت داخلی در
فریم‌ورک گنجانده شده، برای تیم‌هایی که می‌خواهند این موارد را از صفر
نسازند، نقطهٔ شروع نسبتاً کامل‌تری نسبت به ساخت دستی یک لایهٔ Tool روی
یک اپلیکیشن موجود فراهم می‌کند — به‌شرط پذیرش ریسک‌های معمول یک پروژهٔ
Beta.

## مقایسه با گزینه‌های مشابه

رویکرد غالب در اکوسیستم فعلی (برای نمونه الگوهای Agent Middleware و
Deep Agents در LangChain، که پیش‌تر در همین آرشیو پوشش داده شده‌اند)
معمولاً از این مسیر عبور می‌کند: یک Agent جدا ساخته می‌شود و سپس Toolها
و حافظهٔ آن به‌صورت مجزا پیکربندی می‌شوند، در حالی که رابط کاربری همچنان
یک لایهٔ مستقل باقی می‌ماند. تفاوت اصلی Agent-Native در این است که
رابط کاربری و Agent را از ابتدا «همتا» در نظر می‌گیرد و هر دو را مستقیماً
به یک تعریف Action و یک پایگاه‌داده متصل می‌کند؛ این یک مزیت معماری
برای اپلیکیشن‌های تازه‌ساخت است، اما به این معنا نیست که جایگزین کامل
فریم‌ورک‌های Agent عمومی‌تری مثل LangGraph برای Orchestration پیچیدهٔ
چندعاملی باشد — این دو ابزار مسئله‌های هم‌پوشان اما نه کاملاً یکسانی را
حل می‌کنند.
