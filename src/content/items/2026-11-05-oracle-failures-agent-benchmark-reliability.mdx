## این موضوع چیست و چرا الان مطرح شده؟

با رشد سریع بنچمارک‌های Agent (ارزیابی کارهایی مثل رزرو بلیت، کار با
پایگاه‌داده یا دستکاری فایل)، همهٔ توجه معمولاً روی «عملکرد مدل» است:
کدام مدل امتیاز بالاتری می‌گیرد. این مقاله — با عنوان «When Agent
Evaluation Becomes Unreliable» و منتشرشده در ۱۲ اکتبر ۲۰۲۶ — سؤال
متفاوتی می‌پرسد: اگر خودِ هارنس ارزیابی (نرم‌افزاری که محیط را اجرا
می‌کند، ورودی تولید می‌کند و تصمیم قبول/رد می‌گیرد) باگ داشته باشد، چه
اتفاقی برای جدول امتیازها می‌افتد؟ این سؤال برای هر تیمی که از یک
بنچمارک برای تصمیم‌گیری دربارهٔ انتخاب مدل یا معماری Agent استفاده
می‌کند، اهمیت مستقیم دارد.

## چه زمانی و برای چه کسی کاربرد دارد؟

این مقاله برای هر تیمی که روی یک بنچمارک Agent — خودساخته یا عمومی —
برای تصمیم‌گیری دربارهٔ انتخاب مدل، معماری Prompt یا نسخهٔ جدید یک
Agent تکیه می‌کند حیاتی است. پیام اصلی: پیش از اعتماد به یک عدد
بنچمارک، باید از درستی خودِ Harness ارزیابی (نه فقط عملکرد مدل) اطمینان
حاصل کرد. Replication Package منتشرشده (شامل مجموعهٔ تزریق عیب و
اسکریپت‌های تحلیل آفلاین، بدون نیاز به شبکه یا کلید API) این کار را
برای تیم‌های دیگر عملی‌تر می‌کند.

## مقایسه با گزینه‌های مشابه

برخلاف بسیاری از مقالات بنچمارک که روی «رتبه‌بندی مدل‌ها» تمرکز دارند،
این مقاله روی «اعتبار خودِ ابزار رتبه‌بندی» تمرکز می‌کند — یک زاویهٔ
نسبتاً کم‌توجه در ادبیات ارزیابی Agent. از نظر روش، حسابرسی مبتنی بر
Invariant با رویکردهای رایج‌تر «مقایسهٔ خروجی مدل با پاسخ انسانی»
تفاوت دارد، چون روی درستی خودِ فرایند داوری تمرکز می‌کند، نه روی درستی
پاسخ مدل.
