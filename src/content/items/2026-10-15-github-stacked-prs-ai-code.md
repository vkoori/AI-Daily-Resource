summary: >
  مشکلی که این مطلب حل می‌کند: Agentهای کدنویسی اغلب PRهایی با بیش از هزار
  خط تولید می‌کنند که بازبینی آن‌ها عملاً متوقف می‌شود، بازبین زمینه را از
  دست می‌دهد و کیفیت بازخورد افت می‌کند. راه‌حل پیشنهادی GitHub، استفاده از
  Stacked Pull Requestها برای خروجی Agent است، نه فقط برای کار انسانی: (۱)
  ویژگی را بر اساس دغدغه تفکیک کنید (مثال مقاله: کاتالوگ داده، API جست‌وجو،
  اتصال چت، و رابط کاربری با Citation)، هرکدام یک مسئولیت؛ (۲) شاخه پایه Stack
  را از ابتدا مشخص کنید چون قوانین CI/Merge نسبت به آن ارزیابی می‌شوند؛ (۳)
  هر لایه از لایه زیرین خودش شاخه می‌گیرد تا هر PR فقط تغییرات خودش را نشان
  دهد؛ (۴) به هر لایه یک Agent تخصصی اختصاص دهید (مثلاً Agent داده، Backend،
  Frontend)؛ (۵) از افزونه CLI به‌نام `gh stack` به‌همراه یک Skill برای Agentها
  استفاده کنید (دستورهای push، submit، rebase، sync). توصیه مهم امنیتی: دکمه
  Rebase در وب روی سرورهای GitHub اجرا می‌شود و Commitها با کلید شما امضا
  نمی‌شوند؛ وقتی Branch Protection به Commit امضاشده نیاز دارد، باید
  `gh stack rebase` را محلی اجرا و سپس Push کرد. برای بازبینی: ابتدا از بالا
  به پایین برای گرفتن زمینه، سپس از پایین به بالا چون هر لایه به لایه‌های
  زیرین وابسته است؛ به هر لایه یک چک‌لیست بازبینی اختصاصی (اعتبارسنجی ورودی،
  قرارداد پایدار پاسخ، مدیریت خطا/حالت خالی، ردیابی خروجی تا داده واقعی)
  بدهید و CI را روی تک‌تک لایه‌ها، نه فقط بالای Stack، بررسی کنید.
