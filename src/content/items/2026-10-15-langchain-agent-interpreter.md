summary: >
  این مطلب از می ۲۰۲۶ است اما همچنان راهنمای روشنی برای یک تصمیم معماری مهم
  در ساخت Agent است، به همین دلیل به‌عنوان محتوای مرجع ثبت می‌شود. مسئله:
  وقتی Agent فقط یک Tool را در هر نوبت صدا می‌زند، هر نتیجه میانی باید به مدل
  برگردد — این کار رفت‌وبرگشت اضافه می‌سازد، Context را پر می‌کند و تأیید
  کارهای چندمرحله‌ای را سخت می‌کند؛ Sandbox کامل این مشکل را حل می‌کند اما
  راه‌اندازی سنگین‌تری دارد و دسترسی گسترده‌ای به محیط می‌دهد. راه میانه که
  LangChain معرفی می‌کند «Interpreter» است: یک Runtime کوچک و محدود (QuickJS،
  اجرای TypeScript در Deep Agents) که Agent داخل حلقه خودش کد علیه آن
  می‌نویسد. ویژگی‌های کلیدی: به‌طور پیش‌فرض هیچ دسترسی به فایل‌سیستم، شبکه،
  Shell یا نصب Package ندارد و فقط از طریق Bridgeهای صریح که توسعه‌دهنده
  مجاز کرده قابلیت اضافه می‌شود؛ با Programmatic Tool Calling (PTC)، Toolهای
  مجاز به‌صورت تابع Async زیر فضای‌نام `tools` در دسترس‌اند تا Agent بتواند
  آن‌ها را در کد ترکیب کند؛ متغیرها بین فراخوانی‌ها باقی می‌مانند، پس فقط
  عبارت نهایی به مدل بازمی‌گردد، نه حالت‌های میانی؛ محدودیت‌های حافظه، Timeout
  هر اجرا، سقف تعداد فراخوانی Tool و اندازه نتیجه هم قابل‌تنظیم‌اند. چه زمانی
  از چه چیزی استفاده کنیم: Tool Calling معمولی برای کارهایی که مدل باید روی
  هر مشاهده استدلال کند مناسب‌تر و برای Debug/ارزیابی ساده‌تر است؛ Interpreter
  برای کارهای چندمرحله‌ای که نتایج میانی عمدتاً خوراک گام بعدی‌اند (تبدیل
  داده ساختاریافته، واگذاری موازی به Subagentها، پردازش حجم زیاد سند) مناسب
  است و طبق گزارش اولیه تا ۳۵٪ توکن کمتر مصرف می‌کند؛ Sandbox کامل برای کار
  در سطح محیط (اجرای دستور، نصب Dependency، کار با فایل) با نیاز به Isolation
  سطح فرایند/VM باقی می‌ماند.
