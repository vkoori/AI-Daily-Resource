## چه مشکلی را حل می‌کند؟

Agentهای AI که به فایل‌سیستم، شبکه و اپلیکیشن‌های دیگر دسترسی دارند، یک
سطح حملهٔ تازه ایجاد می‌کنند: چه از طریق Prompt Injection و چه به‌خاطر خطای
خودِ مدل، یک Agent ممکن است به فایل یا سروری دسترسی پیدا کند که قرار نبوده.
راه‌حل رایج تا امروز عمدتاً «آموزش دادن» به مدل بود (Alignment، دستورالعمل
System Prompt)، اما این روش یک محدودیت اساسی دارد: تصمیم محدودسازی داخل
همان فرایندی گرفته می‌شود که می‌خواهیم محدودش کنیم. تیم Windows Platform
با MXC این مرز را به بیرون از مدل منتقل می‌کند.

## چه زمانی باید از این الگو استفاده کرد؟

<Callout type="tip">
  اگر در حال ساخت یک Agent هستید که به فایل‌سیستم محلی، مرورگر یا شبکهٔ کاربر
  دسترسی دارد (نه فقط یک API متنی)، تعریف محدودیت دسترسی را از همان ابتدا
  در سطح سیستم‌عامل یا Sandbox طراحی کنید، نه فقط در System Prompt. MXC یک
  نمونهٔ آمادهٔ متن‌باز برای این الگو است؛ حتی اگر از خودِ MXC استفاده نکنید،
  ایدهٔ «Policy جدا از مدل، اجراشده توسط یک لایهٔ مستقل» را می‌توان با ابزارهای
  مشابه (مثل Sandbox کانتینری یا پروفایل‌های دسترسی سیستم‌عامل) هم پیاده کرد.
</Callout>
