## این موضوع چیست و چرا مهم است؟

مدل‌های عمومی بزرگ عمدتاً روی دادهٔ عمومی وب آموزش دیده‌اند، پس اصطلاحات
داخلی یک سازمان، سیاست‌های انطباق (Compliance)، کدبیس اختصاصی، یا
فرایندهای عملیاتی‌اش را نمی‌شناسند. علاوه‌براین، سازمان‌های حساس به
حاکمیت داده (Data Sovereignty) اغلب نمی‌خواهند وابسته به یک API خارجی
بمانند و ترجیح می‌دهند مالک وزن‌های مدل خودشان باشند. Mistral در ۱۷
مارس ۲۰۲۶، Forge را دقیقاً برای پر کردن همین شکاف معرفی کرد: سیستمی که
شرکت‌ها را قادر می‌سازد مدل‌های «درجهٔ فرونتیر، اما ریشه‌دار در دانش
اختصاصی خودشان» بسازند.

  ریسک اصلی است — «ورودی بی‌کیفیت، خروجی بی‌کیفیت» — و آماده‌سازی داده
  می‌تواند ماه‌ها طول بکشد. به بیان این تحلیل، «Forge برای همه مناسب
  نیست».

## چه زمانی و برای چه کسی کاربرد دارد؟

Forge برای سازمان‌هایی منطقی است که سه شرط را هم‌زمان دارند: حجم زیادی
دانش داخلی منحصربه‌فرد (اسناد مهندسی، سیاست‌های انطباق، کدبیس بزرگ)،
الزام حاکمیت داده که مانع تکیه بر یک API خارجی می‌شود (مثلاً در دفاع،
مالی یا بخش دولتی)، و بودجه/تیم فنی کافی برای چرخهٔ آموزش-ارزیابی-استقرار
چندماهه. برای اکثر تیم‌های محصول که فقط می‌خواهند یک Chatbot یا یک
Agent با دانش داخلی داشته باشند، مسیر RAG + API معمولاً سریع‌تر، ارزان‌تر
و کم‌ریسک‌تر است؛ Forge بیشتر شبیه ساخت زیرساخت فیزیکی است تا یک ابزار
تنظیم سریع، و باید به همین چشم دیده شود.
