## این موضوع چیست و چرا الان مهم است؟

وقتی یک Agent کدنویسی مثل Claude Code ساعت‌ها روی یک کار کار می‌کند،
Context آن (تاریخچهٔ مکالمه، خروجی ابزارها، فایل‌های خوانده‌شده) به‌سرعت
رشد می‌کند. مدیریت این Context — چه زمانی خلاصه‌اش کنیم، چه چیزی را
Cache کنیم، چطور فهرست بزرگ ابزارها را بدون اشغال کل پنجره در اختیار مدل
بگذاریم — دقیقاً همان چیزی است که این روزها «Context Engineering» نامیده
می‌شود. Changelog رسمی Claude Code در بازهٔ ۹ تا ۲۲ اکتبر ۲۰۲۶ (نسخه‌های
۲.۱.۲۹۶ تا ۲.۱.۳۰۹) چند قطعه از این پازل را به‌روزرسانی کرده است.

## چه زمانی/برای چه کسی کاربرد دارد؟

این تغییرات بیشتر برای کسانی اهمیت دارند که Claude Code را در جریان‌های
کاری طولانی یا Agentic استفاده می‌کنند: مکالمه‌های چندساعته، Subagentهای
موازی، یا اتصال به دهِ‌ها ابزار از طریق MCP. اگر معمولاً مکالمه‌های کوتاه
دارید، این تغییرات تأثیر قابل‌لمسی روی تجربهٔ روزمره‌تان نمی‌گذارند؛ اما
برای تیمی که Pipeline یا Harness خودش را روی Claude Code می‌سازد، نکات
عملی مهمی دارند — مثلاً دیگر لازم نیست Compaction را دستی و زمان‌بندی‌شده
صدا بزنید، و اگر از یک Gateway سفارشی (ANTHROPIC_BASE_URL) استفاده
می‌کنید، از این پس Tool Search را به‌صورت پیش‌فرض و بدون تنظیم اضافه
دریافت می‌کنید.

<Callout type="tip" title="نکتهٔ کاربردی">
  اگر Pipeline شما به Compaction دستی یا زمان‌بندی‌شده برای مکالمه‌های
  طولانی وابسته بود، با فعال‌شدن Idle Compaction خودکار بررسی کنید که آن
  منطق دستی تکراری یا حتی در تناقض با رفتار پیش‌فرض جدید نشود. همچنین اگر
  از Gateway سفارشی استفاده می‌کنید، فعال‌شدن پیش‌فرض Tool Search یعنی
  رفتار فراخوانی ابزار ممکن است نسبت به قبل کمی تغییر کند؛ ارزش دارد پس از
  ارتقا یک بار جریان کاری خودتان را تست کنید.
