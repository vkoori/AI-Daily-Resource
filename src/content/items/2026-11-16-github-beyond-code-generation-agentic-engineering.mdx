## این موضوع چیست و چرا الان مطرح شده؟

در دو سال گذشته، بحث اصلی دنیای کدنویسی با AI حول «چقدر سریع‌تر می‌توانیم
کد بنویسیم» بوده است. GitHub در این پست — نوشتهٔ Nick Liffen و Philip
Holleran، منتشرشده در ۶ نوامبر ۲۰۲۶ — استدلال می‌کند که این سؤال اشتباه
است: تولید کد دیگر گلوگاه اصلی نیست، بلکه برنامه‌ریزی، بازبینی و پایش
کاری هستند که AI آن‌ها را سریع‌تر نکرده و حتی گاهی سخت‌تر هم کرده است.

## چه مشکلی را حل می‌کند؟

وقتی ابزارهای AI کد بیشتری سریع‌تر تولید می‌کنند، حجم کاری که باید برنامه‌ریزی،
بازبینی، تست و پایش شود هم به همان نسبت بالا می‌رود. طبق این پست، GitHub
افزایش قابل‌توجهی در تعداد Commitها و Pushها مشاهده کرده، اما این یعنی حجم
کاری انسانی در اطراف آن کد — نه نوشتن آن — همچنان گلوگاه باقی مانده است.
نتیجه، همان پدیده‌ای است که بسیاری از تیم‌ها آن را به‌صورت تجربی حس
کرده‌اند: AI نوشتن کد را سریع‌تر کرده، اما صف بازبینی را طولانی‌تر.

## چه زمانی و برای چه کسی کاربرد دارد؟

این چارچوب بیشتر برای تیم‌هایی مفید است که از ابزارهای Agentic کدنویسی
(چه GitHub Copilot، چه Claude Code، چه ابزارهای مشابه) فراتر از «چت با
AI برای نوشتن یک تابع» استفاده می‌کنند و می‌خواهند این استفاده را به
سطح یک فرایند تیمی ببرند. نقطهٔ شروع پیشنهادی ساده است: یک کار جاری را
انتخاب کنید و از خودتان بپرسید این کار به چه Context نیاز دارد، چطور آن
را بازبینی و تست می‌کنید، و پس از انتشار چطور می‌فهمید که واقعاً کار کرده
است — سپس این الگو را به‌تدریج به بقیهٔ فرایند تیم گسترش دهید.
