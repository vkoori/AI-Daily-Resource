## این موضوع چیست و چه مشکلی را حل می‌کند؟

**Speculative Decoding** روشی برای سریع‌تر کردن Inference مدل‌های زبانی
بزرگ است: به‌جای این‌که مدل اصلی (Target Model) هر Token را یکی‌یکی
تولید کند، یک مدل کوچک‌تر و سریع‌تر (Draft Model) چند Token را حدس
می‌زند و مدل اصلی فقط آن‌ها را به‌صورت موازی تأیید یا رد می‌کند. مشکل
این است که تنظیم بهینهٔ این روش به ترکیب مدل Draft، مدل Target، نوع
GPU و این‌که درخواست‌ها به‌صورت تکی یا دسته‌ای (Batch) پردازش می‌شوند
بستگی دارد — و یک تنظیم ثابت برای همهٔ حالت‌ها کار نمی‌کند. برای مثال،
وقتی درخواست‌ها Batch می‌شوند، هر درخواست به محاسبات Attention و حافظهٔ
وضعیت جدا نیاز دارد، و این باعث می‌شود شتاب اولیهٔ Speculative Decoding
تا نیمی کاهش یابد. **SpecPilot** (پژوهشگران NVIDIA، UC Berkeley، Princeton
و Stanford) به‌جای تنظیم دستی برای هر حالت، یک حلقهٔ Agentic طراحی کرده
که خودش این بهینه‌سازی‌ها را کشف می‌کند.

## چرا برای مهندسان زیرساخت AI اهمیت دارد؟

نکتهٔ مهم این مقاله فقط عدد شتاب نیست، بلکه خودِ روش: به‌جای این‌که
مهندسان انسانی برای هر ترکیب جدید از مدل/GPU/Batch Size دستی تنظیم کنند،
یک حلقهٔ Agentic این کار را انجام می‌دهد و فقط تغییراتی را می‌پذیرد که
با Token Forcing، تأییدشده و بدون افت کیفیت باشند — الگویی که می‌تواند
به بهینه‌سازی‌های دیگر زیرساخت Inference (نه فقط Speculative Decoding)
هم تعمیم یابد. برای تیم‌هایی که مدل‌های بزرگ را Serve می‌کنند، توصیهٔ
عملی این است: اگر از Speculative Decoding استفاده می‌کنید، شتاب واقعی
را زیر بار Batch واقعی خودتان بسنجید، نه فقط با عدد تک‌درخواست تبلیغاتی؛
فاصلهٔ بین ۱۰٫۸۷× و ~۲-۴× در حالت Batch می‌تواند تصمیم‌های ظرفیت و
هزینهٔ شما را به‌طور قابل‌توجهی تغییر دهد.
