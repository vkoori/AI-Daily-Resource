## این موضوع چیست و چرا هنوز مهم است؟

Model Context Protocol (MCP) — پروتکل بازی که Anthropic برای اتصال
مدل‌های زبانی به ابزارها و منابع داده معرفی کرد — در ۲۸ ژوئیهٔ ۲۰۲۶ یک
نسخهٔ مشخصات تازه منتشر کرد که به‌گفتهٔ خودِ تیم MCP، تغییراتِ آن
«قابل‌توجه» (Breaking) است. هرچند این بروزرسانی چند ماه پیش منتشر شده، اما
چون یک تغییر معماریِ بنیادی در نحوهٔ طراحی MCP Serverهای تولیدی است و هر
تیمی که همین امروز یک Server جدید می‌سازد یا یک Server قدیمی را به مقیاس
بزرگ‌تر می‌برد با آن روبه‌رو می‌شود، شناختنش همچنان ارزش آموزشی دارد.

<Callout type="fact" title="واقعیت تأییدشده">
  در بخش احراز هویت، سرورهای مجوزدهی باید پارامتر iss طبق RFC 9207 را
  برگردانند و Client پیش از تبدیل کد به Token باید آن را بررسی کند — این
  حفرهٔ «ترکیب‌شدن سرورهای مجوزدهی» (Authorization-server Mix-up) را
  می‌بندد. Dynamic Client Registration (DCR) رسماً منسوخ شده و Client ID
  Metadata Documents (CIMD) روش ترجیحی تازه است، هرچند DCR هنوز کار
  می‌کند. این جزئیات مستقیماً از صفحهٔ رسمی Changelog مشخصات گرفته شده‌اند.
</Callout>

<Callout type="analysis" title="تحلیل/ادعای منبع">
  طبق تحلیل مستقل WorkOS، این نسخه هم‌راستاییِ MCP را با OAuth 2.1 و OpenID
  Connect جدی‌تر کرده (از جمله الزام Resource Indicators طبق RFC 8707 برای
  جلوگیری از سوءاستفاده از Token در سرورهای دیگر)، و استدلال می‌کند که پیش
  از این، احراز هویت MCP عمدتاً به سلیقهٔ پیاده‌سازها واگذار شده بود. این
  یک قضاوت تحلیلی از یک منبع ثالث (یک شرکت ارائه‌دهندهٔ زیرساخت احراز
  هویت) است، نه متن رسمی خودِ مشخصات.
</Callout>

## چه زمانی و برای چه کسی کاربرد دارد؟

این تغییرات برای هر تیمی که یک MCP Server تولیدی را پشتِ چند Instance و
یک Load Balancer معمولی (بدون Session Storage مشترک) اجرا می‌کند حیاتی
است — چون دیگر هر درخواست می‌تواند بدون نیاز به چسبندگیِ Session
(Session Affinity) روی هر Instance پردازش شود. طبق راهنمای مهاجرتِ خودِ
تیم MCP، کدی که به شناسهٔ Session وابسته بود باید بازنویسی شود: به‌جای
تکیه بر وضعیتِ پنهانِ لایهٔ انتقال، باید وضعیت را به‌صورت صریح — مثلاً از
طریق یک Handle که توسط یک ابزار صادر می‌شود — در آرگومان‌های قابل‌مشاهده
برای مدل منتقل کرد.

نیست، بلکه یک تغییر معماری است که باید از قبل برایش برنامه‌ریزی کرد.
