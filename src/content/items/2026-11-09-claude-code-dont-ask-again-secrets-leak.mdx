## این موضوع چیست و چرا الان مطرح شده؟

وقتی در Claude Code یک دستور Shell برای اجرا پیشنهاد می‌شود، معمولاً از
کاربر اجازه می‌خواهد. یکی از گزینه‌های پاسخ، «Yes, and don't ask again»
است — یعنی «این دستور را همیشه بدون پرسش دوباره اجرا کن». شرکت امنیتی
Apiiro در تاریخ ۷ نوامبر ۲۰۲۶ گزارشی منتشر کرد که نشان می‌دهد وقتی کاربر
این گزینه را انتخاب می‌کند، Claude Code عین رشتهٔ همان دستور را در فایل
پروژه‌ای `.claude/settings.local.json` به‌عنوان یک قانون مجوز دائمی ذخیره
می‌کند. مشکل اینجاست: اگر آن دستور شامل یک رمز عبور، توکن یا کلید API
به‌صورت Inline باشد (مثلاً یک رشتهٔ اتصال پایگاه‌داده)، همان رمز هم عیناً
و به‌صورت متن ساده در فایل ذخیره می‌شود. این خبر همین هفته با پوشش
The Hacker News و واکنش مستقیم مسئول Claude Code در Anthropic در
Hacker News به یک موضوع داغ در جامعهٔ توسعه‌دهندگان تبدیل شد.

## چرا این موضوع برای توسعه‌دهندگان Vibe Coding مهم است؟

این مورد نمونهٔ دقیقی از یک الگوی پرتکرار در مهندسی AI است: ویژگی‌ای که
برای راحتی طراحی شده (پرسیدن مکرر اجازه، خسته‌کننده است) بدون طراحی
امنیتی کافی، به یک کانال نشت تبدیل می‌شود. تیم‌هایی که از Claude Code یا
ابزارهای مشابه برای کدنویسی Agentic استفاده می‌کنند باید فایل‌های تنظیمات
محلی این ابزارها را دقیقاً مثل فایل‌های `.env` در نظر بگیرند: هرگز آن‌ها
را Commit نکنند، رمزها را هرگز Inline در دستورات ننویسند، و فرض نکنند
یک محافظت پیش‌فرض (مثل gitignore سراسری) در همهٔ شرایط کار می‌کند. این
خبر همچنین یادآوری می‌کند که Review کردن خودِ تنظیمات امنیتی تولیدشده
توسط AI — نه فقط کد تولیدشده — بخشی جدی‌نشدنی از یک گردش‌کار امن است.
