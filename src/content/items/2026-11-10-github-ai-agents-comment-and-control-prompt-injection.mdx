## این موضوع چیست و چرا هنوز مهم است؟

این یک خبر تازه نیست — افشای اصلی در آوریل ۲۰۲۶ اتفاق افتاد — اما الگویی
را نشان می‌دهد که هنوز در عمل رایج است و هر تیمی که Agent کدنویسی را به
GitHub Actions وصل می‌کند باید آن را بشناسد: **Prompt Injection غیرمستقیم**
(Indirect Prompt Injection). در این حمله، دستور مخرب نه در پیام کاربر، بلکه
در محتوایی که Agent خودش می‌خواند — عنوان یک Pull Request، متن یک Issue،
یا یک کامنت — پنهان می‌شود. وقتی Agent آن محتوا را در زمینهٔ (Context) خود
بارگذاری می‌کند، دستور مخفی را هم مثل یک دستور معتبر اجرا می‌کند.

## چه کاری باید انجام داد؟ (توصیه‌های CSA)

برای تیم‌هایی که Agent کدنویسی را در GitHub Actions اجرا می‌کنند، یادداشت
CSA این اقدامات عملی را توصیه می‌کند: کار با محتوای ورودی از PR و Issue
(که از بیرون قابل‌کنترل است) را طوری فرض کنید که همیشه می‌تواند حاوی دستور
مخرب باشد؛ رمزهای غیرضروری را از محیط Runner حذف و دسترسی توکن‌های باقی‌مانده
را به حداقل محدود کنید؛ مجوزهای `GITHUB_TOKEN` را با بلوک `permissions:`
صریح تنگ کنید؛ Actionها را به Commit SHA (نه Tag قابل‌تغییر) Pin کنید؛
کامنت‌های HTML مخفی را پیش از ورود به Prompt حذف کنید (دفاع کامل نیست، فقط
هزینهٔ حمله را بالا می‌برد)؛ اجرای Agent را به مشارکت‌کنندگان معتمد محدود
کنید و برای مشارکت‌کنندگان تازه، تأیید نگهدارنده را اجباری کنید؛ و خروجی
Agent را پیش از انتشار برای اسرار اسکن کنید.

## چرا برای مهندسی AI مهم است؟

این مورد نمونه‌ای درس‌آموز از یک الگوی تکرارشونده است: هر Agent که محتوای
«غیرقابل‌اعتماد» (از دید امنیتی، هر چیزی خارج از کنترل مستقیم تیم) را
می‌خواند، سطح حملهٔ تازه‌ای باز می‌کند — حتی وقتی آن Agent از یک آزمایشگاه
معتبر باشد. برای تیم‌هایی که Agent کدنویسی را روی مخازن عمومی یا با
مشارکت‌کنندگان خارجی اجرا می‌کنند، نتیجهٔ عملی روشن است: اسرار Runner را
به حداقل برسانید، فرض کنید هر متن ورودی می‌تواند دستور باشد، و منتظر CVE
یا اطلاعیهٔ رسمی برای واکنش نمانید — چون طبق این مورد، ممکن است هیچ‌وقت
منتشر نشود.
