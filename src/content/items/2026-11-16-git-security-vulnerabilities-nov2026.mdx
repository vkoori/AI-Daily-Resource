## این موضوع چیست و چرا الان مطرح شده؟

Git، سیستم کنترل نسخه‌ای که تقریباً هر پروژه نرم‌افزاری امروز روی آن تکیه
می‌کند، در ۱۰ نوامبر ۲۰۲۶ با مجموعه‌ای از شش آسیب‌پذیری امنیتی اعلام‌شده
روبه‌رو شد. این نوع اعلامیه‌ها به‌طور دوره‌ای از سوی تیم امنیتی خودِ پروژه
Git منتشر می‌شوند — این مورد هفتمین نسخه از این سری اعلامیه‌هاست — اما
اهمیتش برای هر تیم مهندسی این است که Git معمولاً به‌صورت نامرئی در پس‌زمینهٔ
CI/CD، ابزارهای Agentic کدنویسی، و خطوط لولهٔ خودکار اجرا می‌شود؛ یعنی
حمله‌کننده لازم نیست مستقیماً به سیستم شما نفوذ کند، کافی است شما را به
Clone کردن یک مخزن یا پردازش یک Patch مخرب ترغیب کند.

## چه مشکلاتی کشف شده و چگونه کار می‌کنند؟

هر یک از این شش مورد از یک مسیر متفاوت در کد Git سوءاستفاده می‌کند؛
نکتهٔ مشترک همهٔ آن‌ها این است که با پردازش یک ورودی ساخته‌شده و مخرب —
یک مخزن، یک Patch، یا یک جریان Import — فعال می‌شوند، نه با نفوذ مستقیم
به ماشین کاربر.

## چرا این برای تیم‌های مهندسی نرم‌افزار و Agentهای کدنویسی مهم است؟

نکته‌ای که این اعلامیه را از یک آپدیت امنیتی معمولی متفاوت می‌کند، سطح
نامرئی بودن Git در گردش کار امروز است: ابزارهای Agentic کدنویسی، خطوط
CI، و اسکریپت‌های خودکار Deploy همگی به‌صورت برنامه‌نویسی‌شده Git را صدا
می‌زنند، اغلب روی مخازن یا Patchهایی که از منابع خارجی یا مشارکت‌کنندگان
ناشناس می‌آیند. مسیر حمله مانند «Clone بازگشتی یک مخزن» یا «اعمال یک
Binary Patch» دقیقاً همان کارهایی است که یک سیستم خودکار بدون نظارت
انسانی هر روز انجام می‌دهد؛ به همین دلیل این‌جا به‌روزرسانی سریع ابزار
Git در Pipelineهای خودکار، نه فقط لپ‌تاپ شخصی توسعه‌دهنده، اهمیت ویژه‌ای
دارد.
