## این موضوع چیست و چرا الان مطرح شده؟

آرشیو این سایت پیش‌تر Copilot Fusion (مسیریابی خودکار مدل برای هر Task)
را در تاریخ ۶ نوامبر پوشش داده است. اما همان اعلامیهٔ GitHub Universe
2026 (۲۸ اکتبر ۲۰۲۶) شامل چند تغییر دیگر هم بود که مستقیماً به نحوهٔ کار
روزمرهٔ تیم‌های مهندسی با Agentهای کدنویسی مربوط می‌شود — مهم‌ترینش
**Copilot Projects**. تا پیش از این، اگر یک تیم چند Repository مرتبط به
هم داشت (مثلاً یک Microservice و Repository‌های کلاینت آن)، باید برای هر
کدام جداگانه Agent راه می‌انداخت و پیشرفت هرکدام را جدا دنبال می‌کرد.
Copilot Projects این کار را در یک صفحهٔ واحد جمع می‌کند: چند نشست Agent
به‌صورت موازی و مدیریت‌شده در چند Repository اجرا می‌شوند و کاربر فقط
پیشرفت و تصمیم‌های لازم (مثل تأیید یک تغییر یا پاسخ به یک سؤال Agent) را
در یک محل پیگیری می‌کند.

## چرا برای تیم‌های مهندسی اهمیت دارد؟

نکتهٔ عملی Copilot Projects این است که واحد کار Agentهای کدنویسی را از
«یک Repository» به «یک محصول/پروژه» تغییر می‌دهد — که واقعی‌تر به نحوهٔ
کار واقعی تیم‌هاست، چون بسیاری از قابلیت‌های واقعی یک محصول، چند
Repository را هم‌زمان درگیر می‌کنند (مثلاً Backend، Frontend و SDK). قبل
از اتکای کامل به اتوماسیون‌های خودبهبودیابنده، نکتهٔ احتیاطی مهم است:
چون این اتوماسیون‌ها بر اساس «نتایج قبلی» پیشنهاد اصلاح می‌دهند، تیم‌ها
باید فرایند تأیید انسانی برای این پیشنهادها را از روز اول جدی بگیرند،
نه این‌که فرض کنند خودبهبودی به‌معنای خودکارسازی کامل بدون نظارت است.
