## این موضوع چیست و چه مشکلی را حل می‌کند؟

تیم‌هایی که همزمان از چند ابزار کدنویسی AI استفاده می‌کنند — مثلاً یک
نفر با GitHub Copilot کار می‌کند، دیگری با Claude Code و سومی با Cursor
— معمولاً باید Instructionها، Promptها، Skillها و تنظیمات سرورهای MCP
را برای هر ابزار جدا و به‌صورت دستی تنظیم کنند. این تنظیمات معمولاً وقتی
یک همکار تازه مخزن را Clone می‌کند یا پروژه را روی ماشین دیگری اجرا
می‌کند، از دست می‌رود یا باید دوباره از صفر ساخته شود. **APM (Agent
Package Manager)**، پروژهٔ متن‌باز مایکروسافت، همین مشکل را حل می‌کند:
دقیقاً مثل این‌که `package.json` و `npm install` وابستگی‌های کد یک
پروژه را مدیریت می‌کنند، APM وابستگی‌های «Context» یک پروژه AI — یعنی
Instructionها، Skillها، Agentها، Promptها و سرورهای MCP — را در یک فایل
`apm.yml` ثابت و قابل‌نسخه‌بندی اعلام و نصب می‌کند.

<Callout type="analysis" title="بلوغ پروژه و دقت فرمت مانیفست">
  مستندات رسمی خودِ پروژه فرمت فایل apm.yml را یک «قرارداد در حال تکمیل»
  (Working-Draft) توصیف می‌کند و می‌گوید نسخه‌های قدیمی‌تر این فرمت، شکل
  «Git به‌همراه مسیر» را نمی‌پذیرفتند. این یعنی ساختار دقیق فایل ممکن
  است هنوز تغییر کند؛ پروژه سطح بلوغ رسمی (مثل GA یا Beta) را اعلام
  نکرده، فقط آن را «متن‌باز» معرفی می‌کند. تیم‌هایی که می‌خواهند از آن
  در زیرساخت CI/CD حساس استفاده کنند، باید نسخه‌های apm.yml را با دقت
  Pin کنند و به‌روزرسانی‌های فرمت را دنبال کنند.
</Callout>

## چرا این موضوع برای مهندسی AI و Vibe Coding مهم است؟

APM نمونه‌ای از یک الگوی مهم‌تر در حال شکل‌گیری در مهندسی AI است: هر
اندازه که Skillها، Promptها و تنظیمات MCP پیچیده‌تر و حیاتی‌تر در گردش‌کار
روزانهٔ تیم‌ها می‌شوند، نیاز به زیرساختی برای نسخه‌بندی، توزیع و
بازتولیدپذیری آن‌ها — دقیقاً مثل کد خودِ برنامه — بیشتر می‌شود. برای
تیم‌هایی که در حال حاضر از چند ابزار کدنویسی AI به‌صورت موازی استفاده
می‌کنند یا با مشکل «روی ماشین من کار می‌کرد» در تنظیمات AI مواجه‌اند،
APM یک راه‌حل عملی و رایگان برای رسیدن به یک منبع واحد و قابل‌اعتماد از
Context است — هرچند باید توجه داشت که این ابزار همچنان در مراحل اولیهٔ
تکامل فرمت خود قرار دارد.
