## مسئله: «Context Rot»

پنجره Context هر مدل زبانی هرچقدر هم بزرگ باشد، نامحدود نیست. در یک Agent
طولانی‌مدت که مدام Tool صدا می‌زند، نتایج جست‌وجو می‌گیرد و پیام رد و بدل
می‌کند، Context به‌تدریج پر از اطلاعات کم‌ارزش و تکراری می‌شود. این پدیده —
که در این مقاله «Context Rot» نامیده شده — باعث افت قابل‌اندازه‌گیری کیفیت
استدلال مدل می‌شود، حتی اگر از نظر فنی هنوز در محدوده مجاز Context Window
باشیم. راه‌حل، صرفاً «پنجره بزرگ‌تر» نیست؛ راه‌حل، مدیریت فعال آن چیزی است
که وارد Context می‌شود.

## چرا این مهم است: RAG به‌تنهایی کافی نیست

<Callout type="tip">
  نکته کلیدی برای تیم‌های مهندسی Agent این است: RAG و جست‌وجوی برداری مسئله
  «بازیابی دانش بیرونی» را حل می‌کنند، اما مسئله جداگانه‌ای هم وجود دارد —
  تجمیع خود تاریخچه مکالمه، نتایج Tool، و کارهای میانی Agent. این دو مسئله
  باید جداگانه مدیریت شوند؛ راه‌حل RAG جایگزین مدیریت فعال Context نمی‌شود.
</Callout>

نکته دوم و مهم برای استقلال بلندمدت تیم شما: حافظه Agent (چه کوتاه‌مدت و
چه بلندمدت) باید در ذخیره‌سازی‌ای بماند که خودتان کنترلش می‌کنید — یک فایل،
یک دیتابیس، یک سیستم داخلی — نه چیزی که صرفاً داخل یک مدل یا یک Provider
خاص نگه‌داری می‌شود. این‌طور اگر روزی مدل یا Provider را عوض کردید، حافظه
انباشته‌شده Agent از بین نمی‌رود.
