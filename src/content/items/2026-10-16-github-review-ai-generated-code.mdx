## چرا بازبینی کد AI به یک چک‌لیست متفاوت نیاز دارد؟

کد تولیدشده توسط AI می‌تواند دقیقاً همان مشکلاتی را داشته باشد که کد انسانی
دارد — به‌علاوهٔ چند دسته خطای مخصوص به خودش: APIهایی که اصلاً وجود ندارند،
محدودیت‌هایی که نادیده گرفته شده‌اند، یا حتی تستی که به‌جای رفع‌شدن،
حذف یا Skip شده تا «سبز» به‌نظر برسد. GitHub این موارد را به‌عنوان دسته‌ای
جدا از خطاهای معمول کدنویسی معرفی می‌کند که بازبین باید مخصوصاً دنبالش
باشد.

<Callout type="fact">
  **Slopsquatting** دقیقاً چیست؟ وقتی یک مدل، نام یک بستهٔ نرم‌افزاری را
  «توهم» می‌کند (بسته‌ای که واقعاً وجود ندارد یا مشابه یک بسته‌ی واقعی و
  محبوب است)، مهاجمان می‌توانند از قبل همان نام جعلی را در Registryهای
  عمومی ثبت کنند تا نصب آن بسته، کد مخرب را وارد پروژه کند. مستندات GitHub
  صریحاً توصیه می‌کند منشأ و وضعیت نگهداری هر بستهٔ پیشنهادی توسط AI را قبل
  از نصب تایید کنید، نه اینکه فقط اسمش را سرچ کنید.
</Callout>

<Callout type="analysis">
  این یک راهنمای رسمی از خودِ GitHub است، نه یک پژوهش مستقل یا آماری — یعنی
  طبیعتاً ابزارهای خودِ GitHub (Copilot، CodeQL، Dependabot) را به‌عنوان
  راه‌حل پیشنهادی معرفی می‌کند. اصل هر هشت محور (به‌ویژه تفکیک خطاهای خاص AI
  و توجه به Slopsquatting) اما مستقل از این‌که از کدام ابزار استفاده کنید،
  معتبر و قابل‌استفاده است.
</Callout>
