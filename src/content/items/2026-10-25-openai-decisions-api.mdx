## این موضوع چیست و چرا الان مهم است؟

بخش بزرگی از کاری که یک اپلیکیشن یا Agent واقعی انجام می‌دهد، تولید متن
آزاد نیست؛ تصمیم‌های کوچک و مکرر است: «این تیکت به کدام تیم برود؟»،
«این تصویر محصول آسیب‌دیده است یا نه؟»، «شدت این باگ چقدر است؟». تا
امروز رایج‌ترین راه برای این کار، فراخوانی یک مدل زبانی بزرگ با یک
پرامپت طولانی و گرفتن یک پاسخ متنی بود که باید بعداً Parse می‌شد —
کاری که هم کند است، هم گاهی خروجی غیرقابل‌پیش‌بینی می‌دهد. اوپن‌ای‌آی
با **Decisions API** مسیر `/v1/decisions` را معرفی کرده که دقیقاً برای
همین دسته از «تصمیم‌های محدود» ساخته شده، نه برای مکالمه یا نوشتن متن.

## چه مشکلی را حل می‌کند؟

وقتی یک تیم مهندسی بخواهد با یک مدل زبانی عمومی مثل خودِ GPT-6 Luna از
طریق Responses API یک تصمیم ساده بگیرد، باید پرامپت بنویسد، منتظر یک
پاسخ متنی بماند، آن را Parse کند، و امیدوار باشد خروجی همیشه با همان
فرمت برگردد. Decisions API این مسیر را کوتاه می‌کند: به‌جای متن آزاد،
یک پاسخ **تایپ‌شده** و همراه با درجه اطمینان عددی برمی‌گرداند — یعنی
همان چیزی که یک سیستم تولیدی برای مسیریابی (Routing)، فیلتر کردن یا
رتبه‌بندی به آن نیاز دارد، بدون پیچیدگی Prompt Engineering برای
قالب‌بندی خروجی.

## چه زمانی و برای چه کسی کاربرد دارد؟

این API برای تیم‌هایی مناسب است که در حال حاضر از یک مدل زبانی عمومی
برای یک وظیفه طبقه‌بندی یا مسیریابی ساده استفاده می‌کنند و بخشی از
زمان و هزینه خود را صرف Parse کردن خروجی متنی و مدیریت خطاهای فرمت
می‌کنند — مثلاً مسیریابی تیکت‌های پشتیبانی، تشخیص پرداخت تکراری، یا
رتبه‌بندی شدت یک باگ. محدودیت مهم: چون فقط روی gpt-6-luna کار می‌کند،
تیم‌هایی که به مدل یا Provider دیگری متعهدند، یا به استدلال پیچیده‌تر
از حد یک «تصمیم محدود» نیاز دارند، باید همچنان از Responses API معمولی
یا معماری‌های دیگر مثل Jev استفاده کنند. از آنجا که این بازار (مدل‌های
تصمیم) تازه شکل گرفته، ارزیابی مستقل و طولانی‌مدت از دقت واقعی هر دو
گزینه هنوز در دسترس نیست.
