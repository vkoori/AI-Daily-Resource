## این موضوع چیست و چرا الان ارزش یادگیری دارد؟

Agentهای کدنویسی مدرن (مانند Claude Code) هر روز روش‌های بیشتری برای
پیکربندی Context خودشان ارائه می‌دهند — فایل‌های راهنما، دستورات Slash،
Skillها، Subagentها، سرورهای MCP و Hookها. این مقاله، که در ۵ فوریهٔ
۲۰۲۶ توسط Birgitta Böckeler (مهندس برجستهٔ Thoughtworks با تمرکز بر
توسعهٔ کمک‌گیرنده از AI) در مجموعهٔ «Exploring Gen AI» روی وب‌سایت
مارتین فاولر منتشر شد، با وجود گذشت چند ماه هنوز به‌عنوان یکی از
واضح‌ترین چارچوب‌های فکری برای این موضوع شناخته می‌شود — دقیقاً نوع
محتوایی که PIPELINE این آرشیو آن را «مفهوم بنیادی ارزشمند، حتی اگر ترند
روز نباشد» می‌نامد. به همین دلیل این مطلب با `kind: reference` و تاریخ
انتشار اصلی ثبت شده، نه به‌عنوان خبر تازه.

مسئلهٔ اصلی که این مقاله به آن می‌پردازد ساده اما حیاتی است: Context
Window هر Agent محدود است، و تصمیم اینکه چه چیزی در آن قرار بگیرد باید
عمدی و آگاهانه باشد. Context خیلی کم، Agent را «بی‌اطلاع» نگه می‌دارد؛
Context خیلی زیاد، آن را کم‌اثرتر و پرهزینه‌تر می‌کند. نویسنده تعریف
این حوزه را از همکارش Bharani Subramaniam نقل می‌کند و سپس آن را با
نمونهٔ مشخص Claude Code توضیح می‌دهد.

  مشکل‌ساز شود — چون قراردادهای یک تیم لزوماً برای تیم دیگر معنادار نیست.
</Callout>

## چه زمانی و برای چه کسی کاربرد دارد؟

این راهنما مناسب هر مهندسی است که از ابزارهای کدنویسی Agentic (نه فقط
Claude Code، بلکه هر ابزار مشابه) به‌طور روزانه استفاده می‌کند و می‌خواهد
به‌جای حدس‌وگمان، یک چارچوب فکری برای تصمیم‌گیری دربارهٔ CLAUDE.md،
Skillها و تنظیمات MCP داشته باشد. به‌ویژه برای تیم‌هایی که در آستانهٔ
تعریف یک «قرارداد تیمی» مشترک برای Context Engineering هستند — مثلاً
این‌که چه چیزی باید در فایل راهنمای مشترک باشد و چه چیزی باید به
Skillهای اختصاصی واگذار شود — این مقاله نقطهٔ شروع خوبی است.

## چه چیزی واقعیت/توصیهٔ عملی است و چه چیزی دیدگاه شخصی نویسنده است؟

<Callout type="analysis" title="محدودیت صریح‌شده توسط خود نویسنده">
  نکتهٔ مهمی که خود نویسنده به‌صراحت به آن اشاره می‌کند این است که Context
  Engineering «شانس نتیجهٔ خوب را بالا می‌برد، اما نمی‌تواند رفتار Agent
  را تضمین کند» — او این را «توهم کنترل» می‌نامد. یعنی حتی با بهترین
  پیکربندی Context، نظارت انسانی هم‌چنان ضروری باقی می‌ماند و نباید
  Context Engineering را به‌عنوان جایگزین کامل برای بازبینی خروجی Agent
  در نظر گرفت. بقیهٔ محتوای مقاله (تعریف دو دسته ابزار، مثال Claude Code،
  توصیه‌های عملی) بیشتر جنبهٔ راهنمای فنی و تجربهٔ عملی نویسنده دارد تا
  ادعای آماری یا پژوهشی که نیاز به تأیید جدا داشته باشد.
</Callout>
