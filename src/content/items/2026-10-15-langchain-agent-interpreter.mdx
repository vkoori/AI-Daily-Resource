## مسئله: فاصله بین Tool Calling ساده و Sandbox کامل

وقتی یک Agent فقط می‌تواند «یک Tool را صدا بزند و منتظر نتیجه بماند»، هر
گام میانی باید به مدل برگردد تا مدل تصمیم بعدی را بگیرد. برای کارهای
چندمرحله‌ای، این یعنی رفت‌وبرگشت زیاد، Context پر از داده‌های میانی که مدل
واقعاً نیازی به دیدن تک‌تک آن‌ها ندارد، و سختی در تأیید صحت کل زنجیره کار.
راه‌حل رایج دیگر، دادن یک Sandbox کامل (محیط اجرای کد با دسترسی کامل) به
Agent است — اما این راه‌اندازی سنگین‌تری دارد و دسترسی بسیار گسترده‌تری به
محیط می‌دهد، حتی وقتی نیازی به آن نیست.

## راه میانه: Interpreter

<Callout type="analysis">
  این مفهوم (Interpreter محدود، نه Sandbox کامل) یک انتخاب طراحی آگاهانه
  LangChain است، نه تنها راه ممکن؛ هدف آن پر کردن دقیق فاصله بین «Tool
  Calling ساده» و «Sandbox کامل» است.
</Callout>

LangChain مفهوم «Interpreter» را معرفی می‌کند: یک Runtime کوچک و شدیداً
محدود (مبتنی بر QuickJS، با اجرای کد TypeScript در Deep Agents) که Agent
می‌تواند داخل حلقه خودش علیه آن کد بنویسد — بدون نیاز به یک Sandbox کامل.

ویژگی‌های کلیدی این Runtime:

- **بدون دسترسی پیش‌فرض** به فایل‌سیستم، شبکه، Shell یا نصب Package؛ هر
  قابلیتی فقط از طریق Bridgeهای صریحی که توسعه‌دهنده مجاز کرده اضافه
  می‌شود.
- **Programmatic Tool Calling (PTC)** — Toolهای مجاز به‌صورت توابع Async
  زیر یک فضای‌نام مشخص (`tools`) در دسترس Agent قرار می‌گیرند، پس Agent
  می‌تواند آن‌ها را مستقیماً در کد ترکیب کند، نه فقط یکی‌یکی صدا بزند.
- **حالت پایدار بین فراخوانی‌ها** — متغیرها بین اجراها باقی می‌مانند؛ فقط
  عبارت نهایی به مدل بازمی‌گردد، نه همه حالت‌های میانی.
- **کنترل‌های Runtime** — محدودیت حافظه، Timeout هر اجرا، سقف تعداد
  فراخوانی Tool، و محدودیت اندازه نتیجه، همگی قابل‌تنظیم‌اند.

## توصیه عملی

<Callout type="tip">
  اگر Agent شما عمدتاً «یک Tool را صدا می‌زند و منتظر پاسخ یک‌خطی
  می‌ماند»، Tool Calling معمولی احتمالاً برای شما ساده‌تر و قابل‌اشکال‌زدایی‌تر
  است. اما اگر Workload شما شامل تبدیل داده ساختاریافته، واگذاری موازی
  کار به چند Subagent، یا پردازش حجم زیادی سند است — جایی که بیشتر
  نتیجه‌های میانی فقط خوراک گام بعدی‌اند و مدل نیازی به دیدن تک‌تک آن‌ها
  ندارد — یک Interpreter محدود می‌تواند هم توکن مصرفی را کاهش دهد و هم
  Context را تمیزتر نگه دارد، بدون این‌که نیاز به دادن یک Sandbox کامل با
  دسترسی گسترده باشد.
</Callout>
