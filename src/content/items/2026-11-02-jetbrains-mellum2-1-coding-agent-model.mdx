## این موضوع چیست و چرا الان مطرح شده؟

JetBrains در ژوئن ۲۰۲۶ مدل Mellum2 را به‌عنوان یک مدل آمیزهٔ کارشناسان
(Mixture-of-Experts) کوچک و سریع برای تکمیل کد معرفی کرده بود — جایگزینی
برای Mellum ۴میلیاردپارامتریِ قدیمی‌تر، اما بدون قابلیت Agentic واقعی. در
۸ اکتبر ۲۰۲۶، JetBrains نسخهٔ Mellum2.1 را منتشر کرد: بدون تغییر در
معماری، اما با دوری از صِرف تکمیل کد به‌سوی رفتار یک Coding Agent — یعنی
توانایی دنبال کردن دستورهای زبان طبیعی، اجرای وظایف چندمرحله‌ای و رفع باگ
در یک مخزن واقعی.

## چگونه کار می‌کند؟

طبق گزارش‌های مستقل از جمله DataNorth، بیشترِ بهبود Mellum2.1 نسبت به
Mellum2 نه از تغییر معماری، بلکه از آموزش تقویتی روی حجم زیادی از وظایف
شبیه‌سازی‌شده (Sandbox Tasks) آمده — جایی که مدل برای عبور واقعی از تست‌ها
پاداش می‌گیرد، نه صرفاً برای تولید کدی که ظاهراً درست به نظر می‌رسد.

## چه زمانی و برای چه کسی کاربرد دارد؟

Mellum2.1 برای تیم‌هایی مناسب است که می‌خواهند یک Coding Agent سبک و
خودمیزبان (Self-hosted) داشته باشند — مثلاً برای مسیریابی و هماهنگی بین
چند مدل، فشرده‌سازی Context در Pipelineهای RAG، یا انجام زیروظایف یک
Agent بزرگ‌تر (برنامه‌ریزی، اعتبارسنجی، تبدیل فرمت) بدون نیاز به فراخوانی
یک مدل بزرگ و پرهزینه. طبق گزارش DataNorth، در حال حاضر فقط از طریق vLLM
پشتیبانی می‌شود (Ollama و LM Studio «به‌زودی» اعلام شده‌اند)، سرویس API یا
قیمت‌گذاری میزبانی‌شده‌ای وجود ندارد، و حافظهٔ GPU تخمینی برای وزن‌های
BF16 حدود ۲۴ گیگابایت است — یعنی برای اجرای محلی روی سخت‌افزار مصرفی
معمولی هنوز نیاز به برنامه‌ریزی دارد.

## مقایسه با گزینه‌های مشابه

نقطهٔ قوت اصلی Mellum2.1 نسبت به Qwen3.5-9B برتری در LiveCodeBench و
توان عملیاتی ادعاشده است، اما طبق همان گزارش‌ها، Qwen3.5-9B همچنان در
SWE-bench Verified، SWE-bench Pro، Terminal-Bench 2.1 و GPQA Diamond —
یعنی وظایف سخت‌تر و نزدیک‌تر به مخازن واقعی — جلوتر است. به‌عبارت دیگر،
Mellum2.1 گزینهٔ خوبی برای کارهای سریع و سبک در کنار مدل‌های بزرگ‌تر است،
نه جایگزین کامل آن‌ها برای وظایف پیچیدهٔ مهندسی نرم‌افزار.
