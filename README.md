# AI Daily Resource

وب‌سایت آموزشی روزانه هوش مصنوعی — نه صرفاً یک چک‌لیست با لینک به منابع
خارجی. هر خبر، مدل، تکنیک مهندسی یا ابزار توسعه مرتبط با AI، یک مقاله
کامل مستقل روی خودِ سایت می‌شود: توضیح فارسی چیستی/چرایی/نحوه کار،
مقایسه با گزینه‌های مشابه، جداسازی واقعیت از تحلیل، و اینفوگرافیک
(نمودار، جدول مقایسه، مراحل فرایند). تولید و به‌روزرسانی خودکار، هر روز.

## ساختار پروژه

این سایت صرفاً یک چک‌لیست با لینک به منابع خارجی نیست — یک **وب‌سایت
آموزشی کامل** است: هر مطلب یک صفحه مستقل با توضیح کامل، مقایسه و
«اینفوگرافیک» درون‌محتوایی دارد، نه فقط یک کارت خلاصه که به بیرون لینک
می‌دهد.

- `src/content/items/*.mdx` — هر فایل یک مطلب است: frontmatter ساختاریافته
  (`title`, `date` (تاریخ افزوده‌شدن به دیجست), `originalDate` (تاریخ انتشار
  اصلی، اختیاری), `source`, `url`, `category`, `summary`, `tags`, `kind`,
  `verified`) + یک **بدنه آموزشی بلند به فارسی** که در `/items/<slug>/`
  به‌عنوان یک صفحه مقاله کامل نمایش داده می‌شود (نه صرفاً خلاصه).
- `src/components/content/` — کتابخانه کامپوننت‌های «اینفوگرافیک» قابل
  استفاده داخل بدنه MDX: `KeyFacts` (جدول در یک نگاه)، `StatBars` (مقایسه
  میله‌ای یک معیار عددی)، `ComparisonTable` (جدول چندویژگی)، `ProcessSteps`
  (مراحل یک فرایند)، `Callout` (جداسازی واقعیت/تحلیل/نکته/هشدار). پالت
  رنگی این کامپوننت‌ها طبق مهارت `dataviz` اعتبارسنجی شده (`--series-1`
  تا `--series-5` در `tokens.css`، هم برای حالت روشن و هم تاریک).
- `src/layouts/ArticleLayout.astro` و `src/pages/items/[slug].astro` —
  صفحه مقاله کامل هر مطلب (بازگشت به دسته، KeyFacts خودکار از frontmatter،
  بدنه رندرشده، لینک «مشاهده منبع اصلی»، مطالب مرتبط).
- `src/data/categories.json` — رجیستری دسته‌بندی‌ها (slug ↔ برچسب فارسی/انگلیسی). دسته‌بندی جدید را فقط با افزودن یک کلید جدید اینجا اضافه کنید؛ نیازی به تغییر schema نیست.
- `src/styles/tokens.css` — Design Tokens (رنگ، تایپوگرافی، فاصله‌گذاری، شعاع گوشه‌ها، پالت سری‌های داده). **یک‌بار طراحی شده؛ در اجراهای روزانه نباید تغییر کند** (استفاده از کامپوننت‌های `content/` داخل MDX مجاز و انتظار می‌رود — نک. `PIPELINE.md`).
- `src/components/` (خارج از `content/`), `src/layouts/` — کامپوننت‌های پایه قابل استفاده مجدد (کارت مطلب، نشان دسته‌بندی، هدر/فوتر، چیدمان پایه).
- `src/pages/` — صفحه اصلی (آخرین گزارش)، صفحه مقاله (`/items/[slug]/`)، آرشیو (`/archive/`, `/archive/[date]/`)، دسته‌بندی (`/category/[slug]/`)، جست‌وجو (`/search/`).
- `scripts/list-urls.mjs` — همه URLهای موجود در آرشیو را چاپ می‌کند؛ پیش از افزودن مطلب جدید برای جلوگیری از تکرار استفاده می‌شود (`npm run list-urls`).

## اجرای محلی

```bash
npm install
npm run dev       # سرور توسعه
npm run build     # خروجی استاتیک در dist/
```

## انتشار

هر push به شاخه `main` به‌صورت خودکار با GitHub Actions (`.github/workflows/deploy.yml`) build و در GitHub Pages منتشر می‌شود. فعال‌سازی GitHub Pages برای این Repository (Settings → Pages → Source: GitHub Actions) یک‌بار و به‌صورت دستی لازم است.

## فرایند روزانه

یک Scheduled Task روزانه (منطقه زمانی Asia/Tehran) فرایند مستندشده در
[`PIPELINE.md`](./PIPELINE.md) را اجرا می‌کند: بررسی وب برای مطالب جدید،
جلوگیری از تکرار URL، ساخت فایل Markdown برای هر مطلب معتبر، build سایت، و
commit/push نتیجه. برای تغییر فرایند، همان فایل را ویرایش کنید — نیازی به
تغییر تنظیمات Scheduled Task نیست.

## افزودن دستی یک مطلب

یک فایل جدید در `src/content/items/` با نام `YYYY-MM-DD-slug.mdx` بسازید
(حتماً `.mdx`، نه `.md`، چون از کامپوننت‌های `content/` استفاده می‌شود).
برای الگوی کامل به هر یک از فایل‌های موجود در `src/content/items/` نگاه
کنید؛ ساختار کلی:

```mdx
---
title: "Example Title"
date: 2026-10-15
source: "Anthropic"
url: "https://example.com/post"
category: "ai-engineering"
summary: "خلاصه‌ای روشن و دقیق به فارسی از محتوا، اهمیت و کاربرد عملی آن."
tags: ["example", "tag"]
kind: "technique"
verified: true
---

import Callout from '../../components/content/Callout.astro';
import StatBars from '../../components/content/StatBars.astro';

## این موضوع چیست و چرا مهم است؟

چند پاراگراف توضیح آموزشی به فارسی — نه خلاصه‌ای تکراری از frontmatter،
بلکه یک مقاله واقعی: مسئله، راه‌حل، نحوه کارکرد، و کاربرد عملی.

<Callout type="analysis">
  اینجا تحلیل یا نظر منبع را از واقعیت تأییدشده جدا کن.
</Callout>

<StatBars
  metric="نام معیار"
  unit="٪"
  series={[{ label: "گزینه الف", value: 42, highlight: true }]}
/>
```

راهنمای کامل نگارش (کدام کامپوننت کِی، چه بدنه‌ای لازم است، و محدودیت‌های
تغییر طراحی) در [`PIPELINE.md`](./PIPELINE.md) بند ۵ و ۶ آمده است.
